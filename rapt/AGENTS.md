# Project Overview
rapt is a Ubuntu Linux command-line client for querying the Ubuntu archive.  rapt is written in pure async Rust and uses network calls to retrieve package and index data from the Ubuntu archive.  rapt only queries the Ubuntu archive and may download package and index data for local caches.  rapt does not install packages, remove package, or change a system's apt configuration--it only queries the Ubuntu archive to find package information and package dependency relationships.  The rapt crate is a Rust library crate that provide Rust-egonomic wrappers around Ubuntu package queries and exposes them as a public Rust library suitable for use by other Rust applications.  The rapt command-line tool parses command-line arguments, validates the received arguments, and calls the exposed public Rust library which in turn performs the needed network calls to interact with the Ubuntu archive.  Responses from the Ubuntu archive are received and the series package data and indices are stored in a local cache file as needed, and results are formatted for display on the Linux terminal.  The formatted responses are displayed in an easy to read and understand fashion. rapt allows users to query the Ubuntu archive and get Ubuntu package information from the command line, allowing for scripted or programmatic queries. rapt has graceful error-handling in case there are problems reaching the Ubuntu archive or error responses are received.  The default data cache behavior is to use cached data retrieved from the Ubuntu archive in the past hour if possible, otherwise query the Ubuntu archive with network calls.  A unique cache file is created for each Ubuntu series.  Each Ubuntu series cache file is timestamped with the last date and time when the cache file was updated.

All rapt queries must specify a target Ubuntu series (e.g. resolute, noble, jammy, etc.) and may optionally specify one or more pockets (release, proposed, updates, security, backports), one or more components (main, universe, restricted, multiverse), or one or more architectures (amd64, arm64, armhf, ppc64el, s390x, riscv64) to filter query results. If no filters are specified, the following default configuration is used:  release, updates, and security pockets are included; the main, universe, restricted, and multiverse components are included; the amd64, arm64, armhf, ppc64el, s390x, and riscv64 architectures are included.

Query filters are specified by the "--series", "--pocket", "--component", and "--arch" command line flags.  "--series" is a required parameter and only accepts a single target Ubuntu series as an argument.  "--pocket" accepts one or more pocket arguments: 'release', 'proposed', 'updates', 'security', 'backports'.  "--component" accepts one or more component arguments: 'main', 'universe', 'restricted', 'multiverse'.  "--arch" accepts one or more architecture arguments: 'amd64', 'arm64', 'armhf', 'ppc64el', 's390x', 'riscv64'.  There are also inverse filter flags that mean "all of the items in the set except the specified items".  These inverse filter flags accept between one and N-1 items where N is the number of items in the set.  Either a query filter flag or its respective inverse query filter flag may be used, but not both because they are mutually exclusive.  The inverse query filter flags are "--not-pocket", "--not-component", and "--not-arch".  "--not-pocket" is the inverse query filter for "--pocket" and accepts between one and four pocket arguments.  "--not-component" is the inverse query filter for "--component" and accepts between one and three component arguments.  "--not-arch" is the inverse query filter for "--arch" and accepts between one and five architecture arguments.

## Query Sub-Commands
rapt offers the following sub-commands for specific queries to run against the Ubuntu archive.  Most of these commands are similar to what the Ubuntu `apt-cache` provides, but do not interact with the host Ubuntu operating system to read or write `apt` configuration nor read or write to the Ubuntu operating system's `apt` package cache.  Sub-commands that take a positional package name argument are shown with the notation 'PKG' where the package name to query should go.  Some sub-commands accept an optional package version number appended to the package name with an '=' character as a delimiter; these are shown using the notation '[=PKG_VERSION_NUMBER]' for the sub-commands that accept the optional package version number parameter.  Sub-command arguments ending with '...' accept one or more parameters to allow batching of queries for more efficiency.  For example, a sub-command with "PKG..." would accept one or more package name parameters; a sub-command with "PKG[=PKG_VERSION_NUMBER]..." would accept one or more package name parameter each of which could have an optional package version number.
- `update` : update the local rapt package cache.  This is done implicitly by all sub-commands that use the cache if it is missing or outdated.  This sub-command will always attempt to update the local rapt package cache for the given series even if it is present and not outdated.
- `showpkg` PKG... : display information about the package(s).  The available versions of the package are listed.  For each available package version, the forward dependencies and reverse dependencies of each listed.
- `showsrc` PKG... : display information about the source package(s). All versions of the source package are shown.
- `stats`: display some statistics about the local rapt package cache.  Statistics reported include:
    - total package names: the number of package names in the cache.
    - normal packages: the number of normal package names.  These packages have a one-to-one correspondence between their names and the names used by other packages for them in dependencies.  Most packages fall into this category.
    - pure virtual packages: the number of packages that exist only as a virtual package name; these packages only define a particular virtual package name but no package actually uses the virutal package name. For example, "mail-transport-agent" is a pure virtual package; several packages Provide "mail-transport-agent", but there is no package named "mail-transport-agent".
    - single virutal packages: the number of packages with only one package providing a particular virtual package. For example, "X11-text-viewer" is a virutal package, but only one package "xless", Provides "X11-text-viewer".
    - mixed virtual packages: the number of packages that either Provide a particular virtual package name or have a virtual package name as the package name.  For example, "debconf" is both an actual package and a virtual package name because a package named "debconf" exists and another package "debconf-tiny" Provides "debconf".
    - missing: the number of package names that were referenced in a dependency but were not Provide'd by any package.  Missing packages may be evidence that a package (real or virtual) has been dropped from the Linux distribution.  Usually they are referenced from Conflicts or Breaks statements.
    - total distinct versions: the number of packages found in the cache.
    - total dependencies: the number of dependency relationships declared by all packages in the cache.
- `dump`: shows a short listing of every package in the cache.  This sub-command is primarily for debugging.
- `unmet`: display a summary of all unmet dependencies in the local rapt package cache.
- `show` PKG[=PKG_VERSION_NUMBER]... : show the full package record(s) for the named package(s).
- `search` REGEX... : perform a full text search on all available package lists using the provided regular expression REGEX.  This search the package names and descriptions for an occurrence of the regular expression and prints out the package name and the short description, including virtual package names.  If the "--full" flag is given, the output identical to the 'show' sub-command output is produced for each matching package.  If the "--names-only" flag is given, only package name and Provide'd packages are searched; the long description is not searched.  Multiple REGEX arguments can be used to specify multiple search patterns that are logically AND'ed together.
- `depends` PKG[=PKG_VERSION_NUMBER]... : shows a listing of each dependency a package has and all the possible other packages that can fulfill that dependency.
- `rdepends` PKG[=PKG_VERSION_NUMBER]... : shows a listing of each reverse dependency a package has.
- `pkgnames` [PREFIX] : prints the name of each package in the local rapt package cache.  The optional PREFIX argument is used to filter the name list to all packages that start with the given prefix.  The package names include both real packages and virtual packages.
- `madison` PKG... : attempts to mimic the output format and functionality of the `madison` archive management tool.  Displays available versions of a package in a tabular format.
- `version`: prints the rapt tool version and exits.

## Folder Structure
- `/src`: top-level Rust source code folder
- `/src/bin`: binary entry points for the application; the rapt.rs source code for the rapt command-line tool is found here
- `/src/lib.rs`: top-level library for shared modules and functionality
- `/test`: top-level folder for integration tests
